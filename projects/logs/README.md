# 项目二：解析日志并找出错误来源

[项目总览](../README.md) · [源码](../../scripts/projects/logs.py)

## 要解决的问题

日志中可能同时出现正常记录、错误记录和损坏格式。需要先说明哪些行能解析，再统计错误来自哪些组件。

## 先预测，再运行

```bash
bash scripts/study.sh project logs
```

events.log 格式为“时间 级别 组件 消息”。前 8 行合法，第 9 行故意写成 BAD RECORD。预计结果：INFO 4、WARN 1、ERROR 3；camera 错误 2、network 错误 1；invalid_lines=[9]。

## 如何阅读代码

正则 fullmatch 检查整行格式；Counter 累加级别与错误组件；格式错误独立报告。空白行不当成记录。report.json 保存统计，程序对照已知输入检查结果。

这个示例检查时间的外观格式，没有完整验证日历日期；如要处理真实日志，还需验证日期、时区和轮转文件，并明确重复记录的处理方式。

## 自己动手

另建程序或输入，在教学数据中增加一条 camera 错误和一条格式损坏记录。手工预测：合法记录 9、ERROR 4、camera 3，格式问题共 2 条。再与程序输出比较。

用 grep 管道对合法输入计算错误组件计数，和 Python 结果交叉比较；说明管道为何不会自动告诉你哪些行格式坏了。

## 完成标准

能解释每项计数的分母；不会把格式错误静默丢弃；能定位异常行号；不把“错误最多的组件”直接当成已经证明的根因。
